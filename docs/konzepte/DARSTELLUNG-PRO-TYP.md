# Darstellung pro Mail-Typ

**Stand:** 15.11.2026

Eine Rechnung ist kein Gespräch, ein Newsletter keine Akte. Jeder Mail-Typ bekommt deshalb seine eigene Darstellung – abgeleitet aus dem, was man mit ihm **tun** will. Die Rohmail bleibt immer erreichbar („Original anzeigen“), ist aber nie die erste Ansicht.

## Gemeinsame Grammatik

Damit die Vielfalt nicht in Chaos kippt, folgt jeder Typ denselben vier Regeln:

| Baustein | Bedeutung |
|---|---|
| **Kopf** | Die 2–5 Fakten, die zählen, extrahiert und gross (Betrag, Frist, Code …) |
| **Hauptaktion** | Genau **ein** primärer Knopf (Antworten, Bezahlen, Kündigen, Kopieren …) |
| **Lebenszyklus** | Wann es auftaucht, wann es verschwindet – sichtbar gemacht |
| **Verlaufsform** | Welche Form der Verlauf auf Zoomstufe „mittel“ annimmt |

Dazu überall gleich: Typ-Farbe in der Themen-Wabe, Hexagramm-Glyph als Status, „Warum hier?“-Begründung, Original-Mail per Tipp.

## Übersicht

| Typ | Leitbild | Kopf | Hauptaktion | Lebenszyklus | Verlaufsform |
|---|---|---|---|---|---|
| **Korrespondenz** | Gespräch | Wer, Thema, wer ist dran | Antworten | bleibt, bis erledigt | Chat · Partitur · Quipu pro Kontakt |
| **Rechnung** | Beleg | Betrag, Fälligkeit, Status-Stempel | An Banking-App | offen → bezahlt → Archiv | Quipu pro Rechnungssteller |
| **Vertrag** | Akte | Partner, Laufzeit, Kündigungsfrist, Kosten | Frist merken / Kündigen | lebt bis Vertragsende | Lebenslinie mit Kündigungsfenstern |
| **Systemmail** | Anzeigetafel | Absender, aktueller Zustand | – (nur lesen) | verschwindet, wenn Zustand final | eine Zeile pro Quelle, nur letzter Stand |
| **Newsletter** | Kiosk | Titelbild, Thema, Lesedauer | Lesen / Abmelden | verblasst bis zur Löschung | Ausgaben-Stapel pro Absender |
| Ticket | Bordkarte | Datum, Ort, Sitz, Code | In Wallet | taucht vor dem Ereignis auf | Reise-/Ereignis-Zeitstrahl |
| Code | Countdown | Code riesig, Restzeit | Kopieren | brennt ab, verschwindet | keine |

## 1. Korrespondenz – das Gespräch

Echte Mails von Menschen: privat und geschäftlich.

```
┌───────────────────────────────────┐
│ 🏠 Küche neu · M. Keller   ䷀ du  │
│ Offerte angenommen, Montage 20.11.│
│ Offen: Rechnung CHF 4'200         │
├───────────────────────────────────┤
│ ┌ Keller ───────────────┐         │
│ │ Gerne, anbei Offerte. │         │
│ └──────────────── 5.11. ┘         │
│          ┌ Ich ───────────────┐   │
│          │ Passt, wir nehmen. │   │
│          └───────────── 6.11. ┘   │
│ [ ✨ Antwortvorschläge ]  [Antworten]│
└───────────────────────────────────┘
```

- Zusammenfassungs-Kopf, darunter Chat ohne Zitate (siehe Spez. 5.8).
- **Zusagen und Entscheidungen** als kleine Stempel im Verlauf („✔ Termin bestätigt“).
- **Erwartete Antwort:** Fragen an mich werden markiert; Warte-Anzeige, wenn ich auf jemanden warte („seit 9 Tagen keine Antwort – nachhaken?“).
- Geschäftlich vs. privat: gleiche Form, geschäftlich zusätzlich mit Signatur-Daten des Absenders (Firma, Telefon) als Visitenkarte.
- Querformat: Partitur. Kontaktseite: Jahresringe + Quipu-Schnur.

## 2. Rechnung – der Beleg

```
┌───────────────────────────────────┐
│ Swisscom                 ┏━━━━━━┓ │
│ Rechnung November        ┃ OFFEN┃ │
│                          ┗━━━━━━┛ │
│        CHF 82.00                  │
│   fällig in 12 Tagen (27.11.)     │
│   ▲ +3.00 gegenüber Oktober       │
│                                   │
│   ▣ QR-Zahlteil    📄 PDF         │
│ [     An Banking-App senden     ] │
└───────────────────────────────────┘
```

- Gestaltet wie ein **Beleg**: Betrag gross, Fälligkeit als Countdown, **Status-Stempel** (OFFEN rot → BEZAHLT grün, schräg aufgestempelt mit Animation).
- **Preisvergleich** zur letzten Rechnung desselben Stellers: Erhöhungen sofort sichtbar.
- **Herkunft des Status:** „bezahlt laut Mail vom 3.11.“ / „wird per Lastschrift belastet“.
- Archiv als **Quipu pro Rechnungssteller**: jeder Knoten eine Rechnung, Knotengrösse = Betrag, Summe pro Jahr am Schnurende; Ausreisser (doppelte Rechnung, Preissprung) farbig.
- Mailtext nur aufklappbar – er interessiert fast nie.

## 3. Vertrag – die Akte *(neue Kategorie)*

Mietverträge, Versicherungspolicen, Abos, Handyverträge, Arbeitsverträge, AGB-Änderungen, Vertragsbestätigungen.

```
┌───────────────────────────────────┐
│ 📁 Helsana · Grundversicherung    │
│ Partner    Helsana AG             │
│ Kosten     CHF 412.– / Monat      │
│ Laufzeit   1 Jahr, verlängert sich│
│ Kündigung  bis 30.11. (in 15 Tg)⚠ │
├───────────────────────────────────┤
│ 2024 ──●────────┃▓▓┃──────●──▶    │
│ 2025 ───────────┃▓▓┃──●───────▶   │
│ 2026 ───────────┃▓▓┃───────────▶  │
│        Abschluss  ▓ Kündigungsfenster│
│ [ Frist merken ]  [ Kündigen … ]  │
└───────────────────────────────────┘
```

- **Akten-Kopf mit Eckdaten**, extrahiert aus Mail und Anhang (PDF): Vertragspartner, Vertragsnummer, Beginn, Laufzeit, automatische Verlängerung, Kündigungsfrist, nächster Kündigungstermin, Kosten.
- **Lebenslinie** statt Thread: Abschluss, Änderungen, Preisanpassungen und **Kündigungsfenster** als markierte Zonen.
- **Änderungen als Vergleich:** Bei AGB- oder Preisänderungen zeigt die App, *was* sich geändert hat (z. B. „Prämie +6 %“, „Kündigungsfrist neu 3 statt 1 Monat“).
- **Erinnerung vor Kündigungsfristen** (lokale Benachrichtigung, z. B. 30 und 7 Tage vorher); Vertrag erscheint dann auf der Pole Position.
- **Kündigen-Assistent:** KI entwirft das Kündigungsschreiben (Vertragsnummer, Termin, Empfangsbestätigung erbeten); wird nie automatisch versendet.
- **Verknüpfung:** Rechnungen desselben Partners hängen an der Akte („alle Prämienrechnungen“); im Blackboard-Modus mit Fäden verbunden.
- Archiv: **Vertragsordner** nach Lebensbereich (Wohnen, Versicherung, Mobilität, Telekom, Arbeit, Abos) mit Monatskosten-Summe.
- **Erkennung:** Anhänge wie Vertrag/Police/AGB, Begriffe wie „Vertragsbestätigung“, „Ihre Police“, „Laufzeit“, „Kündigungsfrist“, Mails von E-Signatur-Diensten (signierte PDFs).

## 4. Systemmail – die Anzeigetafel

Versandbenachrichtigungen, Bestellbestätigungen, Login-Hinweise, Kontoaktivität, Social-Media-Benachrichtigungen, Server- und Build-Meldungen.

```
┌───────────────────────────────────┐
│ STATUS                       18:14│
│ 📦 Galaxus   ●●●●○ unterwegs, Mo  │
│ 📦 Zalando   ●●●●● zugestellt   ✓ │
│ 🔐 Google    neuer Login Zürich  ⚠│
│ 🔁 GitHub    Build ok  (12× heute)│
│ 💬 LinkedIn  3 Nachrichten        │
└───────────────────────────────────┘
```

- Leitbild **Bahnhofs-Anzeigetafel**: eine Zeile pro Quelle, **nur der aktuelle Zustand**. Zehn Versandmails zur gleichen Sendung werden zu einem Fortschrittsbalken.
- **Gleichartige Meldungen bündeln** („12× Build ok heute“), Abweichungen hervorheben („Build failed“).
- **Sicherheitsrelevantes steigt auf:** neuer Login, Passwortänderung, Kontosperre → Pole Position, mit Hinweis „Warst du das?“.
- **Verschwindet, wenn der Zustand final ist:** „zugestellt“ → nach 7 Tagen weg; „Build ok“ → am nächsten Tag weg.
- Kein Verlauf im eigentlichen Sinn – auf Wunsch die Historie einer Zeile als Mini-Zeitstrahl.

## 5. Newsletter – der Kiosk

```
┌───────────────────────────────────┐
│ KIOSK                Wochen-Digest│
│ ┌──────┐ ┌──────┐ ┌──────┐        │
│ │ ▓▓▓▓ │ │ ▓▓▓▓ │ │ ░░░░ │        │
│ │ NZZ  │ │Heise │ │ IKEA │ ← verblasst
│ │ 6 Min│ │ 3 Min│ │ 2 Tg │        │
│ └──────┘ └──────┘ └──────┘        │
│ 💡 Seit 3 Monaten ungelesen:      │
│    IKEA, Digitec   [ Abmelden ]   │
└───────────────────────────────────┘
```

- Leitbild **Zeitungskiosk**: Raster mit Titelbild pro Absender, oben die neueste Ausgabe, darunter der Stapel älterer Ausgaben.
- **Leseansicht** wie ein Reader: ruhige Typografie, Werbeblöcke zusammengeklappt, geschätzte Lesedauer.
- **Tracking-Schutz:** externe Bilder und Zählpixel standardmässig blockiert, Bilder über einen Tipp nachladbar.
- **Verblassen:** Je näher die automatische Löschung rückt, desto blasser wird die Karte – der Lebenszyklus ist sichtbar, ohne Zahl.
- **Wochen-Digest (On-Device-KI):** „Das stand diese Woche in deinen Newslettern“ in wenigen Punkten mit Sprungmarken.
- **Abmelde-Vorschläge** auf Basis des Leseverhaltens; Abmelden mit einem Tipp (List-Unsubscribe).
- Swipe: rechts = gelesen/weg, links = behalten, hoch = als Lesezeichen merken.

## 6. Ticket und 7. Code

Bereits in der Spezifikation (5.5, 5.6) beschrieben; in diesem Raster:
- **Ticket = Bordkarte:** Querformat-Karte mit Datum, Ort, Sitz und Barcode in voller Helligkeit, Countdown bis zum Ereignis.
- **Code = Countdown:** Ziffern riesig und in Gruppen (`482 913`), ein Ring brennt die Gültigkeit ab, danach löst sich die Karte auf.
